# Clean Code inventory

Source: Robert C. Martin, _Clean Code_. Stack: **typescript** (Expo SDK 58 / React Native).

Lint entrypoint: `npm run lint` (`eslint .`). Typecheck: `npm run typecheck`. Combined gate: `npm run check` (lint + typecheck + tests + knip + jscpd; husky pre-commit). Commit messages: `npm run commitlint` (husky `commit-msg`). Do not use `npx expo lint` as the gate — it only covers `app/`, `src/`, and `components/`.

## Cursor rules convention

- Default: one `.cursor/rules/clean-code.mdc` for judgment (`alwaysApply: true`)
- Split only for different globs or a real boundary seam — currently `unit-tests.mdc` for test files
- Guide-heavy chapters (1, 6, 12, much of 13) stay in the rule file — no extra ESLint plugin for those alone

### VIPER + Clean Architecture layer map (React-adapted)

| Role          | Location                                                                                                                                                                               | Imports                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Builder       | `app/`                                                                                                                                                                                 | `modules/features`, `modules/shared`, `data/sources/` / `data/catalogs/` / `data/mappers/`, `lib/` (`useScheduleSnapshot(scheduleSource())`), `constants/`, `expo-router`                                                                                                                                                                                                                                                                                                                                     |
| Router        | `modules/features/*/router.ts`                                                                                                                                                         | `expo-router`, contracts, entities, shared route helpers (`schedule-game-route`) — no `react-native` / `data/` / sibling features                                                                                                                                                                                                                                                                                                                                                                             |
| View          | `modules/features/*/view.tsx` (+ `components/`)                                                                                                                                        | presenter types, `constants/`, `modules/shared` — no `expo-router`, no data queries, no sibling features                                                                                                                                                                                                                                                                                                                                                                                                      |
| Contract      | `modules/features/*/contracts.ts`                                                                                                                                                      | view-model types for that feature (`GameFilter` is Schedule’s chip selection, not a shared entity). Schedule also owns clock ports (`DayCalendar`, `MatchLabels`, `ScheduleClock`) injected by the Builder.                                                                                                                                                                                                                                                                                                   |
| Presenter     | `modules/features/*/presenter.ts` + `hooks/` + `mappers/`                                                                                                                               | hook in `presenter.ts`; four blank-separated beats: (1) operations with inputs, (2) calling hooks (`useScheduleRouter`, `useDayKey`), (3) other operations needed to build the return (may evolve), (4) return the view model. Beat 4 is mappers only — per-feature `mappers/` (`gameRows`, `dayPager`, `dayLabel`, `competitionDisclosures`, `gameChips`) and shared `notice`. Do not extract a Presenter helper solely to satisfy `max-lines-per-function`; that glob is exempt from the 20-line gate. Mappers are presentation nouns: they turn use-case results into view models. Hooks hold React state (`useDayKey`); use cases are pure application actions. Presenter: use cases, hooks, shared entities/gateways/mappers, contracts, feature `router` — no `react-native` / `expo-router` / `data/` / `lib/` / sibling features. Mappers: entities, gateways, use cases, contracts — no `lib/` (the Builder injects `scheduleClock`). Mappers may call use cases; use cases must not know about view models. |
| Feature hooks | `modules/features/*/hooks/`                                                                                                                                                            | React state the Presenter calls in beat 2 (`useDayKey`). Contracts and use cases — no `react-native` / `expo-router` / `data/` / `lib/` / sibling features / view-model mapping. Not a mapper (no view model) and not a use case (not pure). App-level composition stays in `lib/`; Expo Router stays in `router.ts`. |
| Use cases     | `modules/features/*/use-cases/`, `modules/shared/use-cases/`                                                                                                                           | Application actions over entities, gateway ports, and other use cases (`listMatchesFor`, `relateDay`, `groupByCompetition`) — which matches are listed, how they group, how a day relates to now (`today` / `tomorrow`, or null). Named as verbs. Never `data/`, sibling features, `lib/`, or view-model types. Display copy (`Today`) lives in mappers (`dayLabel`).                                                                                                                                                                                                                                                                                            |
| Gateways      | `modules/shared/gateways.ts`                                                                                                                                                           | entity types and board ports (`GameCatalog`, `MatchCatalog`, `ScheduleLoadState`, `ScheduleBoardState`, `ScheduleBoardSource`); catalogs implemented in `data/`, board source in `lib/board/`                                                                                                                                                                                                                                                                                                                 |
| Entities      | `modules/shared/entities.ts`; feature `entities.ts` when the feature owns some                                                                                                         | domain DTOs (`Game`, `Match`, `Team`); Schedule owns `CompetitionGroup`. Grouping identity is `game` + required `Match.tournament`. Ingest trims titles (`asOrNull.string`, PandaScore `tournamentFrom`). Missing vendor league/stage become `Tournament` at ingest, so `groupByCompetition` keeps those matches in one group per game. Owned JSON drops a row with no tournament.                                                                                                                                                                                                                                                              |
| Shared UI     | `modules/shared/components/`                                                                                                                                                           | widgets used by more than one feature                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Sample / API  | `data/sources/` (`live/`, `pandascore/`, `sample/`), `data/mappers/`, `data/catalogs/`                                                                                                 | PandaScore maps vendor JSON in `data/sources/pandascore/mappers/` and caches the board (`createCachedScheduleBoardLoader`); `data/sources/live/load-schedule-payload` turns a token into the `/api/matches` payload; `data/sources/live/load-schedule` is the device client (owned JSON parsed in `data/sources/live/mappers/`); shared JSON combinators (`asOrNull`, `parseAll`, `parseOptional`) live in `data/mappers/`; `app/api/matches+api.ts` maps that payload to HTTP. Catalogs via `data/catalogs/` |
| Clock / board | `lib/clock/` (`use-now`, `calendar-day`, `schedule-clock`, `device-time-zone`), `lib/board/` (`sample-board`, `schedule-source`, `use-schedule-board`), `lib/use-schedule-snapshot.ts` | infrastructure; clock helpers free of modules; Builders pass `scheduleSource()` into `useScheduleSnapshot`, then pass loaded `board` and `scheduleClock(now, timezone)` into presenters                                                                                                                                                                                                                                                                                                                       |

Feature and shared modules use the same layout when a role exists: `components/`, `hooks/` (React state for the Presenter), `mappers/` (per-module presenter mapping — not a loose file beside `presenter.ts`), `use-cases/`, `contracts.ts`, `entities.ts`, `gateways.ts`, `presenter.ts`, `router.ts`, `view.tsx`, `*.harness.ts`, and colocated `*.test.ts`. Use cases are verbs (pure application actions); mappers are nouns (view-model mapping); hooks hold React state. Cross-feature entities, gateways, use cases, UI, and mapping (`notice`, `schedule-game-route`) live in `modules/shared`; a feature omits `entities.ts` / `gateways.ts` until it owns some. Shared omits presenter / router / view until it is a screen. Enforced with `no-restricted-imports` in `eslint.config.js` (Ch.8 / Ch.11). Expo Router treats every file in `app/` as a route, so composition hooks stay in `lib/` and Builders pass `scheduleSource()` into `useScheduleSnapshot`, then pass the loaded board and `scheduleClock(now, timezone)` into presenters. Extra files under `app/api/` would become routes, so server load/cache lives in `data/`.
